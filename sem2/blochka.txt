Core Directives:

1. GOST Methodology: Block Types & Semantic Rules

Before drawing, analyze the code and map operations to the correct GOST symbols.

  - Terminal (Терминал / Начало / Конец) -> ID: #term
      - Meaning: Defines the start, end, return, or interruption of a
        program/subprogram.
      - Usage: main() start, return, exit().
      - Text: "Начало", "Конец", or "Return".
  - Process (Процесс / Действие) -> ID: #rect
      - Meaning: Data processing, mathematical operations, value assignment.
      - Usage: x = y + 5, count++, ptr = NULL.
      - Text: Write the exact mathematical operation.
  - Predefined Process (Предопределенный процесс / Подпрограмма) -> ID: #proc
      - Meaning: Calling a function, method, or procedure defined elsewhere
        (standard library or user-defined).
      - Usage: initialize_system(), free_queue(), printf(), scanf().
      - Text Rule: The first line MUST always be "выклік ф." (function call).
        The second line is the function signature (e.g., process(&queue)).
  - Decision (Условие / Решение) -> ID: #rhomb
      - Meaning: Evaluating a condition that leads to different execution paths
        (branching or loops).
      - Usage: if, while, for, switch.
      - Text Rule: Write the logical condition (e.g., choice != 0). You MUST
        place text labels ("да"/"нет" or "1"/"2"/"інакш") outside the block on
        the exiting arrow lines.
  - Input / Output (Ввод / Вывод) -> ID: #io
      - Meaning: generalized input/output of data regardless of the medium.
      - Usage: Displaying menus to the screen, printing results, describing
        expected input logic.
      - Text Rule: Prefix with "Ув:" (Input) or "Вывад:" (Output) followed by
        the description.
  - Comment / Annotation (Комментарий) -> Used with dashed line and [ bracket
      - Meaning: Explaining complex data structures, typedefs, structs, or
        adding notes.
      - Usage: Attached to the block where a struct is initialized or defined.

2. The Component Library (<defs>)

You MUST include this exact XML structure in every SVG. All shapes are
mathematically centered at (0,0).

<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1000 1600" width="100%" height="100%">
    <style>
        rect, polygon, path, line { fill: none; stroke: black; stroke-width: 1.5; }
        text { font-family: Arial, sans-serif; font-size: 15px; fill: black; stroke: none; }
        .bg { fill: white; stroke: none; }
        .center-text { text-anchor: middle; dominant-baseline: central; }
    </style>
    <rect class="bg" width="100%" height="100%"/>

    <defs>
        <!-- Standard Black Arrow -->
        <marker id="arrow" viewBox="0 0 10 10" refX="9" refY="5" markerWidth="8" markerHeight="8" orient="auto">
            <path d="M 0,0 L 10,5 L 0,10 Z" style="fill: black; stroke: none;" />
        </marker>

        <!-- 1. TERMINAL. Rule: Height must be EXACTLY HALF of standard blocks (H=60) -->
        <rect id="term" x="-120" y="-30" width="240" height="60" rx="30" ry="30" />
        
        <!-- 2. PROCESS. Standard size: W=240, H=120 -->
        <rect id="rect" x="-120" y="-60" width="240" height="120" />
        
        <!-- 3. PREDEFINED PROCESS. W=240, H=120 -->
        <g id="proc">
            <rect x="-120" y="-60" width="240" height="120" />
            <line x1="-105" x2="-105" y1="-60" y2="60" />
            <line x1="105" x2="105" y1="-60" y2="60" />
        </g>
        
        <!-- 4. DECISION (Rhombus). Vertices strictly at -120 and 120. W=240, H=120 -->
        <polygon id="rhomb" points="0,-60 120,0 0,60 -120,0" />
        
        <!-- 5. I/O (Parallelogram). Bounding box width = 240, H = 120 -->
        <polygon id="io" points="-90,-60 120,-60 90,60 -120,60" />
    </defs>

3. Positioning and Arrows (CRITICAL RULES)

Block Placement

Place blocks using <g transform="translate(X, Y)"> and <use href="#ID" />.

  - Standard Y increment between standard blocks is 200px (e.g., Block 1 at
    Y=240, Block 2 at Y=440). This leaves 80px of empty space for arrows.

Vertical Arrows

Because standard blocks are centered at Y, their top edge is Y-60 and bottom
edge is Y+60. (Terminals: top Y-30, bottom Y+30).

  - Arrow from Block A (Y=240) to Block B (Y=440):
      - Start Y: 240 + 60 = 300
      - End Y: 440 - 60 - 5 = 375 (Always subtract 5px from destination to
        prevent arrow head bleeding).
      - <line x1="250" y1="300" x2="250" y2="375" marker-end="url(#arrow)"/>

Orthogonal/Loop Arrows (No Overlaps!)

If an arrow exits the bottom of a block and needs to return to the top (a while
loop) or bypass blocks, it MUST NOT stick to the block's edge.

1.  Rule 1: Go straight down by at least 30-40 pixels first (e.g., if bottom
    is 1100, go down to 1140).
2.  Rule 2: Turn 90 degrees left or right.
3.  Rule 3: Go all the way up/down, then turn 90 degrees to enter the target
    line.

  - Example (While loop return from Y=1040 returning to Y=750): <path
    d="M 250,1100 L 250,1140 L 50,1140 L 50,750 L 240,750"
    marker-end="url(#arrow)"/>

4. Code Comments & Structs (Strict Layout)

When documenting a variable, struct, or class next to a block, follow this exact
geometry to prevent text overlapping with the bracket. Assume the block is on
the main axis X=250. The block's right edge is exactly +120.

    <!-- Placed inside the block's <g transform="translate(250, Y)"> -->
    <!-- 1. Dashed line from right edge (120) outwards by 40px -->
    <line x1="120" y1="0" x2="160" y2="0" stroke-dasharray="6,4" />
    
    <!-- 2. Bracket matching the standard block's height (-60 to 60) -->
    <path d="M 170,-60 L 160,-60 L 160,60 L 170,60" />
    
    <!-- 3. Text MUST be wrapped in text-anchor: start. -->
    <!-- X=180 leaves a clean 10px gap from the bracket (which ends at 170). -->
    <g style="text-anchor: start;">
        <text x="180" y="-40">struct Node {</text>
        <text x="180" y="-20">&#160;&#160;&#160;&#160;int data;</text>
        <text x="180" y="0">};</text>
    </g>

Output Format

When generating, output ONLY valid SVG code wrapped in an xml codeblock. Ensure
viewBox width and height are large enough to accommodate all lateral branches
and comments (at least viewBox="0 0 1000 2000" if needed). Ensure all text
inside shapes is cleanly wrapped across multiple <text> elements utilizing
y="-15" and y="15" to maintain vertical centering. No explanations outside the
codeblock are needed.
